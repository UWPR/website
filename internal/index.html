Mounting UWPR partitions on local boxes

On Windows, add these network shares:

   \\gs-ddn2.gs.washington.edu\pr-vol1
   \\gs-ddn2.gs.washington.edu\pr-vol2
   \\gs-ddn2.gs.washington.edu\pr-vol3

   and for the username, use "gs/{GSID}"

Linux using sshfs thru tephra:

   sshfs {gsid}@tephra.gs.washington.edu:/net/pr/vol1 /net/pr/vol1
   sshfs {gsid}@tephra.gs.washington.edu:/net/pr/vol2 /net/pr/vol2
   sshfs {gsid}@tephra.gs.washington.edu:/net/pr/vol3 /net/pr/vol3



Processing UWPR searches on tephra:

  • RAW files get moved over to central storage/tephra into their respective project directories
under /net/pr/vol2/ProteomicsResource/{year}/{project}

  • 'cd' to the directory containing the raw files and run "readysearch .". This will create
a corresponding search directory in /net/pr/vol1/ProteomicsResource/search/ProteomicsResource/{year}/,
symlink the RAW files into this directory, and  perform RAW to mzXML conversions using ReAdW.  Once
the conversions are complete, the destination directory will be listed in the output.

  • 'cd' to the destination search directory that you copy/pasted from step 2.

  • Generate a comet.params using "comet -p" or copy one from a previous search. Set the search
parameters.  A list of sequence databases is maintained under /net/pr/vol1/ProteomicsResource/dbase/.
These standard databases are maintained (aka kept around) for many years. If a custom database is needed,
I typically place those in the project search directory e.g. /net/pr/vol1/ProteomicsResource/2025/{project}/.

  • To submit the Comet searches, run "runCometQ *.mzXML".

  • Check status of searches either using the command "qstat -u {gsid}" or by looking at the
search output in the "qsublogs" directory using a command like "cat qsublogs/*".

  • Once searches are complete, run "runCometQ --wocomet --single --prophet0 *.mzXML" to run
xinteract post processing.  If Comet internal decoys were applied, use this command
"runCometQ --wocomet --single --prophet0 --decoy DECOY_ *.mzXML". I see enough issues with
PeptideProphet, especially for samples with low ID counts, that I set the probability filter/cutoff
to 0.0 using the "--prophet0" option.

  • After all of the interact files have been generated, run "datahtml ." which creates a
simple "data.html" file in the search directory. This command also prints out the URL to
this file which gets added as an external data link to on the UWPR webapp project page.  When
adding the external data link, I use the data directory name, e.g. "20250203_Exploris1_hh",
as the text in the Comments field.  I always check that an ".htaccess" file is written to the
search directory as it has failed in the past.  If the ".htaccess" file is not present, try
adding the external data link again or just manually placing an ".htaccess" there.

  • Then email the researchers that their analysis results are available online.

To update, run "/net/pr/vol1/ProteomicsResource/dbase/UniProt/.update/getdb.uniprot_proteomes".
This will download each proteome FASTA, append contaminants, and place them in a newly
created directory /net/pr/vol1/ProteomicsResource/dbase/UniProt/{YYYMMDD}.

These get updated randomly, once or twice yearly, so there's a chance there's newer
versions than the ones listed here.
